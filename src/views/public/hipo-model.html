TALA — Hierarchical Input Process Output (HIPO) Model

A Web-Based Patient Record Management System with Batch Migration for the Rural Health Unit of Paete, Laguna

🌲 HIPO Model Architecture: Naka-istruktura ang buong sistema sa ilalim ng anim (6) na core modules: User Authentication, Patient Registration, Batch Migration (pangunahing pokus ng pag-aaral), Document Digitization & OCR, Clinical Retrieval, at Statistical Reporting & Governance. Bawat sub-module ay may kumpletong breakdown ng INPUT, PROCESS, at OUTPUT.

1.0 User Authentication & Access Control

  • 1.1 Login & Session Handling
    • Input: Staff credentials, CSRF token
    • Process: Bcrypt compare, JWT token signing
    • Output: Active session, role dashboard access
  • 1.2 Staff Account Provisioning
    • Input: Full name, email, role, status
    • Process: Unique email check, password hashing
    • Output: Staff user record, active privileges
  • 1.3 Role Permissions & Profile
    • Input: User ID, profile update, reset request
    • Process: RBAC verification, DB update
    • Output: Updated profile, route access policy

2.0 Patient Registration & Profiling

  • 2.1 Patient Registration
    • Input: Demographics, PhilHealth, 4Ps
    • Process: Validation, generate unique PAT ID
    • Output: Registered patient master record
  • 2.2 Demographic Update & Archive
    • Input: Patient ID, contact update, archive flag
    • Process: Authorization check, status cascade
    • Output: Updated patient profile, active/archived state
  • 2.3 Duplicate Screening & Merge
    • Input: Name, birthdate, threshold
    • Process: Fuzzy algorithm matching, record merge
    • Output: Duplicate warning flag, consolidated master

3.0 Batch Migration & Data Ingestion

  • 3.1 Batch Document Archive Ingestion
    • Input: Legacy archive package (ZIP/Folder, CSV)
    • Process: Format validation, staging in upload queue
    • Output: Staged migration queue, validation summary
  • 3.2 Automated Patient Record Linking
    • Input: Staged legacy documents, ID matching rules
    • Process: ID matching, auto-link to master profile
    • Output: Linked health documents, migration progress log
  • 3.3 Migration Error Handling & Audit
    • Input: Unmatched files, SHA-256 hashes
    • Process: Flag unmapped files, preservation checksums
    • Output: Discrepancy report, verified DB integrity

4.0 Document Digitization & OCR Engine

  • 4.1 Document Upload & Security Check
    • Input: Scanned paper records (PDF, PNG, JPG)
    • Process: Size check (<10MB), MIME check, storage
    • Output: Stored path, temporary staging token
  • 4.2 Automated OCR Text Extraction
    • Input: Staged file, OCR configuration parameters
    • Process: Tesseract.js engine, extract bounding blocks
    • Output: Extracted text content, indexed search text
  • 4.3 Health Binder Auto-Classification
    • Input: OCR text, medical keyword dictionary
    • Process: Keyword matching to 5 binder categories
    • Output: Auto-classified binder record, metadata

5.0 Clinical Retrieval & Unified Search

  • 5.1 Unified Full-Text & OCR Search
    • Input: Keywords, patient name, number, date filters
    • Process: Query DB and OCR index, apply role filter
    • Output: Matching patient records, highlighted snippets
  • 5.2 Clinical Binder Inspection
    • Input: Patient ID, category (ITR, Consult, Vax, etc.)
    • Process: Retrieve binder list, signed download URLs
    • Output: Interactive viewer, chronological health timeline
  • 5.3 Read-Only Healthcare Review
    • Input: Healthcare personnel consultation query
    • Process: Read-only clinical access, fetch history
    • Output: Complete health profile, consultation summary

6.0 Statistical Reporting & Governance

  • 6.1 Demographic & Census Aggregation
    • Input: Date range, barangay, PhilHealth, 4Ps filter
    • Process: Count aggregation, morbidity statistics
    • Output: RHU Paete census report, summary tables
  • 6.2 Compliance Report Export (PDF/CSV)
    • Input: Report dataset, format selection (PDF/CSV)
    • Process: Formatted PDF with RHU header, CSV compile
    • Output: Downloadable PDF report, structured CSV
  • 6.3 System Audit Logging & Preservation
    • Input: Transaction events (Create, Upload, Export)
    • Process: Snapshot capture, trigger verified DB backup
    • Output: Immutable audit trail log, verified DB backup
